# Plusieurs langues avec alweb

`alweb.i18n` sert un site dans la langue de chaque visiteur. Il fournit les catalogues de traductions, le choix
de la langue de chaque requête, les pluriels, et les dates, nombres et montants mis en forme dans cette langue.
Le tout est écrit en ALEX et fonctionne aussi dans l'exécutable natif.

## Mise en place

```al
use alweb.i18n as i18n

func creer(cfg, dossier="."):
    app := alweb.App("Blog")
    ...
    app.middleware([sessions.middleware(secret), csrf.middleware()])
    i18n.I18n(app, os.join(dossier, "locales"), {"default": "fr", "locales": ["fr", "en"]})
```

Créez `I18n` **après** l'intergiciel de sessions : la langue choisie y est retenue. Les catalogues sont des
fichiers `locales/<langue>.json` :

```json
{
  "Se connecter": "Sign in",
  "Bonjour {nom}": "Hello {nom}",
  "commentaires": {"one": "{n} comment", "other": "{n} comments"},
  "compte": {"titre": "Your account", "aide_html": "See the <a href=\"/aide\">help page</a>"}
}
```

**Les clés sont le texte de la langue par défaut.** Une clé sans traduction s'affiche telle quelle, donc le
catalogue français peut rester vide (sauf les pluriels). Pour des clés de type identifiant, utilisez des objets
imbriqués : `"compte": {"titre": …}` donne la clé `compte.titre`. Une clé absente est cherchée dans cet ordre :
la langue demandée (`fr-CA`), sa langue de base (`fr`), la langue par défaut, puis la clé elle-même. En mode
debug, les catalogues sont relus quand ils changent, et chaque traduction manquante est signalée une fois dans
le terminal.

| Option | Défaut | Rôle |
|---|---|---|
| `default` | `"fr"` | langue par défaut |
| `locales` | fichiers du dossier | langues proposées, dans l'ordre du sélecteur |
| `detect` | `["prefix", "param", "user", "session", "cookie", "header"]` | ordre de recherche de la langue |
| `param` | `"lang"` | paramètre `?lang=en` (retenu ensuite dans la session et dans le cookie `alweb_lang`, 1 an) |
| `prefix` | `false` | langue dans l'URL : `/en/articles` (voir plus bas) |
| `user` | — | `fn(req) -> code` : langue préférée du compte connecté |
| `timezone` | `"local"` | fuseau des dates : `"local"` (du serveur), `"UTC"`, `"+01:00"` ou un décalage en secondes |
| `currency` | — | devise par défaut du filtre `currency` |

Avec `I18n`, les erreurs de formulaire, les pages d'erreur et l'administration suivent aussi la langue du
visiteur (voir « Les textes d'alweb »).

## Choix de la langue

La langue de chaque requête est cherchée dans l'ordre suivant :

1. le préfixe d'URL ;
2. `?lang=xx` ;
3. la préférence du compte (option `user`) ;
4. la session ;
5. le cookie `alweb_lang` ;
6. l'en-tête `Accept-Language` du navigateur, avec ses poids `q`.

À défaut, c'est la langue par défaut. Seules les langues proposées sont retenues : si le visiteur demande
`fr-CA` et que seul `fr` existe, il obtient `fr`. S'il demande `en` et que seul `en-GB` est proposé, il obtient
`en-GB`. Un code invalide, comme `?lang=xx%0D%0A…`, est ignoré.

Chaque réponse indique sa langue dans `Content-Language`. Quand la langue vient de l'en-tête du navigateur, la
réponse porte aussi `Vary: Accept-Language`, pour qu'un cache ne serve pas la page anglaise à un lecteur
français.

**Langue dans l'URL** (`"prefix": true`). Les adresses `/en/articles/3` et `/de/articles/3` mènent à la route
`/articles/3`, et `/articles/3` sert la langue par défaut (avec `prefix_default`, elle aussi a son préfixe).
Dans les gabarits, `url_for` garde la langue de la page. Chaque langue a ainsi ses propres adresses, ce que
préfèrent les moteurs de recherche.

## Dans les gabarits

```html
<html lang="{{ lang }}" dir="{{ lang_dir }}">
<h1>{{ _("Bonjour {nom}", {"nom": current_user.nom}) }}</h1>
<button>{{ "Se connecter" | t }}</button>
<h3>{{ _n("commentaires", commentaires | length) }}</h3>
<p>{{ _("compte.aide_html") }}</p>
<p>{{ article.cree_le | date("long") }} · {{ article.cree_le | reltime }}</p>
<p>{{ prix | currency("XOF") }} · {{ vues | number }} · {{ taux | percent(1) }}</p>
<p>{{ _("par {nom}, le {date}", {"nom": a.auteur.nom, "date": i18n.date(a.cree_le, "long")}) }}</p>

<footer>{% for l in locales %}
  {% if l.current %}<strong>{{ l.name }}</strong>
  {% else %}<a href="{{ l.url }}" hreflang="{{ l.code }}">{{ l.name }}</a>{% endif %}
{% endfor %}</footer>
```

| Variable / filtre | Rôle |
|---|---|
| `_(clé, {variables})`, `"clé" \| t` | texte traduit, échappé à l'affichage ; les clés finissant par `_html` donnent du HTML (variables échappées) |
| `_n(clé, n, {variables})` | pluriel ; `{n}` est mis en forme dans la langue (`1 250`, `1,250`) |
| `lang`, `lang_dir` | code de la langue, `ltr` ou `rtl` (arabe, hébreu, persan, ourdou…) |
| `locales` | langues proposées : `code`, `name` (dans sa propre langue), `current`, `url` (même page dans cette langue) |
| `i18n` | le traducteur de la requête, avec ses méthodes `i18n.date(…)`, `i18n.list(…)`, etc. |
| `\| date(style)`, `\| datetime(style)`, `\| time` | styles `short`, `medium` (défaut), `long`, `full`, ou motif `"{EEEE} {d} {MMMM}"` |
| `\| reltime` | « il y a 3 minutes », « in 2 days », « à l'instant » |
| `\| number(décimales)`, `\| currency(devise)`, `\| percent(décimales)` | séparateurs, symbole et position propres à chaque langue |
| `\| list` | « Awa, Bob et Chen » ; `list("or")` donne « … ou … » |

Une date peut être un horodatage (secondes, comme `orm.timestamp`), un texte ISO ou les champs de `time`. Un
horodatage est affiché dans le fuseau de l'option `timezone`. Un texte sans fuseau (`"2026-11-08 14:05"`) est
affiché tel quel. Un texte avec fuseau (`"…Z"`, `"…+01:00"`) est converti.

## Dans le code

```al
tr := i18n.translator(req)
alweb.flash(req, tr.t("Article publié."))
tr.n("commentaires", 3)                            # « 3 commentaires »
tr.date(t, "full")                                 # « dimanche 8 novembre 2026 »
tr.currency(15000, "XOF")                          # « 15 000 F CFA »
tr.locale                                          # « fr »
app.i18n.translator("en").t("Se connecter")        # hors requête : tâche de fond, script
```

## Courriels

```al
await m.send_template(u["courriel"], tr.t("Confirmez votre adresse"), "confirmation", {"lien": lien}, {"locale": u["langue"]})
```

Avec `locale`, le courriel est rendu dans cette langue : `_()`, les dates et les nombres suivent cette langue, et
l'en-tête `Content-Language` est posé. Le gabarit `emails/confirmation.en.txt` est préféré à
`emails/confirmation.txt` s'il existe. L'objet se traduit avec `tr.t(…)`. Un courriel envoyé par une tâche de
fond n'a pas de requête : gardez la langue du compte en base (par exemple `u["langue"]`) et passez-la ici.

## Ce qui est couvert

| | Langues |
|---|---|
| Pluriels (règles CLDR) | français, portugais (Brésil), hindi… (0 et 1 au singulier) ; anglais, allemand, espagnol, italien, néerlandais, langues scandinaves ; russe, ukrainien ; polonais ; tchèque, slovaque ; arabe (6 formes) ; hébreu ; japonais, chinois, coréen, vietnamien, wolof, bambara, yoruba (forme unique) |
| Nombres et montants | fr, fr-CA, fr-CH, en, de, de-CH, es, es-MX, it, pt, pt-PT, nl, ru, uk, pl, sv, tr, ar, ja, zh, ko, hi ; une autre langue prend les formats de sa langue de base, ou à défaut ceux de l'anglais. Devises : symbole et nombre de décimales (XOF, XAF, JPY sans centimes) |
| Dates (noms des mois et des jours) | fr, fr-CA, en, en-GB, de, es, it, pt, nl ; les autres langues ont l'ISO `2026-11-08` tant qu'on n'appelle pas `i18n.register_formats(code, formats, noms)` |
| Temps relatif, listes | fr, en, es, de, it, pt, nl (anglais pour les autres) |

## Les textes d'alweb

alweb fournit lui-même la traduction de ses propres textes ; l'application n'a rien à ajouter :

| Textes | Langues fournies |
|---|---|
| Erreurs de formulaire (`validate_form`, administration) | fr, en, es, de, it, pt, nl |
| Pages d'erreur (400, 401, 403, 404, 405, 408, 413, 415, 422, 429, 500, 502, 503) | fr, en, es, de, it, pt, nl |
| Administration (`alweb.admin`) | fr, en |

**Formulaires.** Les messages s'adressent au visiteur : « Ce champ est obligatoire. », « Au moins 3
caractères. », « Enter a whole number. ». Ils remplacent les messages techniques du schéma (`longueur 2 < 3`).
`f.codes["nom"]` donne le code et ses paramètres (`["too_short", {"n": 3}]`), `f.details["nom"]` le message
d'origine. Le message d'un `sch.custom(prédicat, "déjà pris")` est traduit comme une clé de vos catalogues.
Codes : `required`, `too_short`, `too_long`, `invalid_format`, `not_integer`, `not_number`, `not_text`,
`not_boolean`, `too_small`, `too_large`, `invalid_choice`, `too_few`, `too_many`, `unexpected`, `invalid`. Sans
`I18n` dans l'application, ces messages sont en français.

**Pages d'erreur.** Un navigateur reçoit une page dans sa langue : titre (« Page introuvable », « Seite nicht
gefunden »), explication, message passé à `alweb.abort(…)` et lien vers l'accueil. Le détail d'une exception
n'est pas montré hors mode debug. Une API (`Accept: application/json`) reçoit toujours son JSON. Pour garder
le style du site, ajoutez le gabarit `templates/errors/404.html` (ou `errors/error.html` pour tous les codes) :
il reçoit `status`, `title`, `hint`, `message` et `home`, en plus des variables habituelles. Un
`@app.error_handler(404)` de l'application passe avant tout cela.

**Remplacer un texte d'alweb.** Mettez la même clé dans vos catalogues, par exemple
`"alweb.form.required": "Merci de remplir ce champ."` dans `locales/fr.json`. Pour une autre langue de
l'administration, traduisez ses clés (le texte français : `"Ajouter"`, `"Retour à la liste"`…) dans
`locales/<langue>.json`. La liste complète est dans `alweb/messages.al`.

## La commande `alweb i18n`

```sh
alweb i18n              # clés trouvées dans le code et les gabarits, traductions manquantes par langue
alweb i18n --update     # ajoute les clés manquantes, vides, aux catalogues (à traduire ensuite)
alweb i18n --strict     # code de sortie 1 s'il manque une traduction (intégration continue)
```

La commande cherche les appels `_("…")`, `_n("…", n)`, `"…" | t`, `tr.t("…")` et `tr.n("…", n)` dans les
fichiers `.al` et dans `templates/`. Les clés lancées par `--update` valent `""` (ou `{"one": "", "other": ""}`
pour un pluriel) : elles comptent comme manquantes, et le site retombe sur la langue par défaut tant qu'elles ne
sont pas traduites. Les clés présentes dans un catalogue mais absentes du code sont signalées par `?`, car elles
peuvent être construites à l'exécution. Pour la langue par défaut, seuls les pluriels et les clés de type
identifiant (`compte.titre`) sont exigés. Réglages dans `alweb.json` : `locales`, `templates`,
`default_locale`.
